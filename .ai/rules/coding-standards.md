\# Coding Standards — Full Stack Engineer



\## Princípios Gerais



O agente deve sempre produzir código:



\- simples;

\- legível;

\- organizado;

\- seguro;

\- fácil de manter.



Antes de criar código:



1\. Entender o problema.

2\. Analisar a arquitetura existente.

3\. Planejar a solução.

4\. Implementar.

5\. Testar.

6\. Revisar.



\---



\# Código Limpo



Seguir princípios:



\- nomes claros para variáveis e funções;

\- funções pequenas;

\- evitar duplicação;

\- evitar complexidade desnecessária;

\- separar responsabilidades.



\---



\# TypeScript



Preferir:



\- tipagem forte;

\- interfaces claras;

\- evitar "any";

\- tratamento de erros explícito.



\---



\# React / Next.js



Seguir:



\- componentes pequenos;

\- separar lógica e interface;

\- usar hooks corretamente;

\- evitar componentes gigantes.



\---



\# Banco de Dados



Sempre:



\- validar dados;

\- evitar consultas desnecessárias;

\- criar estruturas escaláveis;

\- proteger informações sensíveis.



\---



\# Revisão



Antes de finalizar qualquer tarefa:



Perguntar:



\- O código está seguro?

\- Existe uma solução mais simples?

\- Está preparado para crescer?

\- Possui tratamento de erros?
